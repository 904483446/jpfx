# 导航集合页修复设计

## 背景与根因

侧栏已链接到 `/app/spaces` 与 `/app/tasks`，但前端仅实现了带标识符的详情页：`/app/spaces/[spaceId]` 与 `/app/tasks/[taskId]`。因此登录用户点击这两个入口时稳定落入 Next.js 404 页面。

## 目标

让两个侧栏入口都落在受保护、可理解且不伪造业务数据的页面上，并保持现有详情路由和 API 契约不变。

## 方案

- `/app/spaces`：使用 `AppShell` 承载现有 `AuthenticatedApp`，复用已验证的用户鉴权、产品空间列表和“新建产品空间”空状态。
- `/app/tasks`：新增只读的任务队列落地页，说明任务从产品空间内创建；当没有可显示的聚合任务 API 时不展示模拟任务、不发起不存在的请求。
- 为两个页面各添加路由级测试；测试只断言页面可渲染、使用统一外壳，并验证任务页指向已有空间入口。

## 非目标与边界

- 不新增或修改后端 API、数据库、任务数据或外部 Provider 调用。
- 不创建演示产品空间、分析任务或报告。
- 不改动现有 `/app/spaces/[spaceId]`、`/app/tasks/[taskId]` 与报告页。
- 截图仅取真实空状态，且不包含用户姓名、邮箱、密钥或 Cookie。
