# V0.3 RAG 检索设计

## 目标与范围

V0.3 将 V0.2 已上传的空间文档转化为可检索的私有知识库：支持 PDF、DOCX、TXT、MD 正文解析、文本清洗与切分、DashScope `text-embedding-v4` 向量化、pgvector 相似度检索，以及空间内检索界面。

本版本不包含 OCR、后台 Worker/队列、混合检索、rerank、分析任务或报告生成。扫描版 PDF 没有可提取正文时标记为失败，不做 OCR。

## 用户流程

1. 用户在自己的空间文档列表中点击“开始索引”或“重新索引”。
2. 后端确认文档、空间和用户归属；状态从 `uploaded` 或 `failed` 更新为 `processing`。
3. 当前请求同步解析原文件，清洗文本、按固定窗口切分，并调用 DashScope 生成 embedding。
4. 成功后写入 chunk 与 pgvector 索引，文档状态更新为 `indexed`；失败则清理本次 chunk，状态更新为 `failed` 并保存中文原因。
5. 用户在空间内输入检索问题，查看 top 8 来源片段、文件名、chunk 序号和相似度。

## 数据与隔离

新增 `document_chunks`：`id`、`user_id`、`space_id`、`knowledge_base_id`、`document_id`、`chunk_index`、`content`、`embedding`、`metadata`、时间戳。数据库迁移启用 pgvector，并创建向量检索索引及 `(user_id, space_id, document_id, chunk_index)` 唯一约束。

所有索引和检索查询同时过滤 `user_id` 与 `space_id`；文档归属检查复用既有服务。响应不暴露存储路径、DashScope Key 或内部向量。

## 处理与错误规则

解析器按格式独立实现：TXT/MD 使用 UTF-8（含 BOM）读取；PDF 使用成熟文本提取库；DOCX 使用成熟文档库。空文本、扫描件、格式损坏、DashScope 调用失败和数据库失败都写入统一中文错误消息。

索引前删除该文档既有 chunk；仅在整批 embedding 与写入成功后保留新 chunk。失败时事务回滚并清理新 chunk，避免混合新旧索引。缺少 `DASHSCOPE_API_KEY` 时拒绝索引并标记失败，不产生伪向量；Key 只从后端环境读取，不进入数据库、前端、日志或测试夹具。

## API 与前端

- `POST /api/v1/documents/{document_id}/index`：启动同步索引，返回更新后的文档状态。
- `POST /api/v1/spaces/{space_id}/retrieval/search`：接收非空 `query` 与可选 `top_k`（默认 8，上限 20），返回来源片段。

文档页为 `uploaded`、`failed` 显示索引/重新索引操作；`processing` 禁用操作；`indexed` 显示已索引。新增空间内检索区，未索引、无结果和接口失败均显示统一中文反馈。

最终执行后端 Ruff/格式/Pytest、前端测试/路由/类型/lint/build/audit，以及真实 Docker PostgreSQL + pgvector 联调。浏览器 Cookie/CORS 联调只在服务启动后执行。
