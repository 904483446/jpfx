# 前端退出登录设计

## 目标

为已登录用户提供可发现、可验证的退出登录入口，复用既有 Cookie 会话与 `POST /api/v1/auth/logout` 接口；退出成功后回到登录页。

## 范围

- 在应用壳顶部栏的“账户设置”旁增加低强调的“退出登录”按钮。
- 在前端认证客户端增加 `logout()` 请求封装。
- 点击后禁用按钮并调用退出接口；接口成功后使用客户端路由替换到 `/login`。
- 接口失败时保留当前页面与会话，恢复按钮并显示可读错误。

不包含：后端接口、Cookie 属性、账户菜单、确认弹窗、额外依赖或视觉体系改造。

## 交互与视觉

按钮沿用现有顶部栏的次级文字操作样式，与“账户设置”并列。正常状态使用中性文字；悬停时增强前景色；提交中显示“退出中…”。不使用危险色，避免把正常会话操作误导为破坏性操作。

## 数据流

`AppShell` 中的退出按钮 -> `auth.logout()` -> `POST /api/v1/auth/logout`（携带 httpOnly Cookie） -> 服务端清除 Cookie -> `router.replace('/login')`。

请求失败时，`auth.logout()` 向组件抛出统一 API 错误；组件展示“退出失败，请稍后重试”，不进行跳转。

## 测试与验收

先写失败测试，覆盖：

1. `logout()` 使用 `POST /auth/logout` 请求。
2. 顶部栏显示唯一的退出按钮。
3. 退出成功后调用 `/login` 路由替换。
4. 提交期间按钮禁用，防止重复请求。
5. 退出失败后显示错误并恢复可操作状态。

通过前端单测后，在本地浏览器完成登录 -> 退出登录 -> 访问 `/app` 被重定向到 `/login` 的验收。
