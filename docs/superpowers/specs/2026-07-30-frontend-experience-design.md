# JPFX 前端体验统一优化设计

## 目标

在不改变路由、认证、API 契约、数据模型和安全边界的前提下，统一 JPFX 全站的视觉层级与阅读路径。产品应呈现为面向产品经理的“竞品研究档案台”，而不是通用仪表盘或聊天界面。

本轮优先让用户清晰理解并操作真实链路：产品空间 → 资料与检索 → 分析任务 → Agent 运行记录 → 报告与导出。

## 已确认的视觉方向

- 保留现有暖米白背景、近黑文字、朱红强调色、细分隔线和克制圆角。
- 保留目录式左侧导航；导航固定包含“研究总览、产品空间、分析任务、报告中心、设置”。
- 不新增伪造数据、客户标识、指标、报告结论或外部 Provider 调用。
- 桌面端以两栏或三栏信息编排提升扫描效率；窄屏回退为单列。
- 状态必须同时用文字和视觉区分，不能只依赖颜色；遵守既有 `prefers-reduced-motion` 规则。

## 页面信息架构

### 首页与认证

- 首页保留产品价值、真实功能流程和登录/注册入口；流程固定为“资料入库、分析任务、报告交付”。
- 登录、注册保留现有字段、校验、错误与跳转行为；仅统一标题、辅助说明、表单间距和按钮层级。

### 应用壳与研究总览

- 左侧导航展示五个真实路由入口，当前项有朱红边线与文字状态。
- 顶栏展示当前位置、账户设置入口和退出登录，不展示邮箱、密钥或其他敏感内容。
- 研究总览以产品空间为核心：空间名称、行业、产品方向、描述与“新建产品空间”主操作；空状态只引导创建首个空间。

### 产品空间、资料与检索

- 空间详情按“资料、检索、关联任务、关联报告”组织。
- 文档状态、失败原因、引用片段和来源保持当前真实 API 数据；相似度不被表述为事实可信度。
- 无资料时提供上传资料的下一步引导，不展示演示资料。

### 分析任务与运行记录

- 任务页将标题、任务状态、阶段进度、失败原因和重试操作置于首屏。
- 七步时间线解释任务生命周期；Agent 运行记录按轮次展示证据收集、质量检查、模型分析和报告生成。
- “证据质量检查”只呈现可用性、来源类型、缺失项和人工确认项，不新增或伪造评分。

### 报告中心与报告详情

- 报告列表保持空间归属与现有筛选规则。
- 详情阅读顺序为：核心结论、竞品对比、建议行动、风险与不确定性、引用证据、导出。
- PDF/DOCX 导出继续复用现有安全 URL 校验与服务端授权；不改变报告或证据数据。

### 设置与用户级模型密钥

- 设置作为左侧导航的固定末项，页面标题为“模型设置”。
- 当前只暴露用户级 DeepSeek Key 配置；Bocha、DashScope 等不新增到该页面。
- 页面只显示“待配置/已配置”、服务端返回的掩码提示与默认模型；完整 Key 仅可在用户输入时短暂存在于受控密码框中，保存后立即清空。
- 安全说明明确：前端不回显、不缓存、不返回完整 Key；服务端按既有加密机制保存。
- 不新增“清除配置”行为，除非后端先提供经过授权、可测试的删除契约；本轮仅优化既有加载、保存、错误和未配置状态。

## 组件边界

- 在现有 `components/evidence` 和 `components/app` 中复用或扩展页面标题、状态印章、空状态、区块标题和说明面板。
- 页面组件只组合既有数据与语义组件；颜色、边距、圆角、状态映射不在页面中重复定义。
- 不增加 UI 依赖、远程字体或设计素材；效果图仅用于设计沟通，不进入项目产物。

## 验收标准

- 所有既有路由、表单字段、API 调用、认证跳转、导出与隔离规则保持不变。
- 受影响前端组件增加或更新测试，先验证失败后完成最小实现。
- `npm.cmd test`、`npm.cmd run check:routes`、`npx.cmd tsc --noEmit`、`npm.cmd run lint` 与 `npm.cmd run build` 通过。
- 桌面和窄屏下导航、标题、操作和状态信息没有重叠、裁切或横向溢出。
- 任何截图、示例或测试都不包含真实邮箱、密钥、Cookie、Token 或 Provider 凭据。

## 非目标

- 不做公开部署、公开 Demo、CI、真实第三方 Provider 调用或跨设备视觉验收。
- 不添加聊天、数据大屏、协作、计费、后台管理或新业务流程。
- 不修改后端、数据库、环境变量、密钥管理契约或现有数据。
