# GitHub 展示型 README 优化设计

## 目标

将 JPFX 的仓库首页从“本地实现说明”调整为“作品集优先的产品展示页”：让招聘方和项目浏览者在 30 秒内理解产品价值、进入线上体验，并看到可信的工程与验证证据；同时保留开发者可复现所需的启动、测试和架构信息。

## 已确认的展示原则

- 首要受众是招聘方、作品集访客和项目浏览者；开发者复现为次要目标。
- 使用真实、已脱敏的页面截图，不录制演示视频，不创建静态伪造 Demo 数据。
- 所有已上线结论都必须与已验证事实一致：Vercel 前端、Railway API 健康检查、认证、文档上传、私有 Supabase Storage 跨重部署、DashScope 文档索引和删除。
- DeepSeek 分析、Bocha 检索等外部 Provider 只表述为“配置后可用”，不宣称已经完成生产真实调用验收。
- README 绝不包含数据库 URI、Supabase Secret Key、DashScope Key、Cookie、Token 或其他真实凭据。

## README 信息架构

1. **首屏定位**：中文项目名、一句话价值主张和正式体验链接 `https://jpfx.vercel.app/`。
2. **产品闭环**：用简洁流程说明“空间 → 私有资料 → 向量索引与检索 → 竞品分析任务 → 证据与报告导出”。
3. **真实界面**：复用现有 `docs/assets/v1-showcase/*-v2.png`，以登录、工作台、任务/报告、模型设置四张图展示现有界面；每张图保留一句说明。
4. **能力边界**：用表格区分“已实现并已验证”“已实现、需用户配置外部 Provider”“未纳入本轮承诺”。
5. **工程可信度**：展示 Next.js/FastAPI/Supabase/PostgreSQL+pgvector/Storage 的职责分工，以及 GitHub Actions CI 和线上部署拓扑。
6. **复现入口**：将本地启动、测试命令和环境变量说明后置；保留最少必要步骤并指向 `.env.example`，不复制真实值。
7. **安全说明与文档导航**：说明私有 bucket、后端密钥边界、用户空间隔离，并链接 PRD、技术规格和任务拆分文档。

## 仓库级整理范围

- 更新根目录 `README.md` 的标题、首屏、部署状态、功能表、验证状态和运行说明。
- 保留现有截图资产；本轮不新增或修改产品页面截图。
- 在 README 增加 GitHub Actions 状态徽章和正式体验链接；若徽章 URL 与当前 workflow 名称不一致，以仓库内 workflow 文件为准。
- 增加“GitHub About 建议”说明：仓库简介、Topics、线上地址由用户在 GitHub 页面设置，不在代码中保存。

## 不在本轮范围

- 不修改产品功能、数据库 schema、部署配置、Provider 调用逻辑或 API 契约。
- 不创建 LICENSE、贡献指南、Issue 模板或演示录屏；这些需要另行确认开源授权和协作目标。
- 不承诺新的真实 Provider 调用或额外付费额度消耗。

## 验收标准

- README 首屏可直接打开正式体验链接，并准确描述已验证的生产闭环。
- 所有截图都来自现有脱敏资产，链接可用。
- README 不含真实凭据、连接串或误导性“全部功能已验证”表述。
- 本地启动与测试命令可读、路径正确，并继续以 `.env.example` 为唯一示例来源。
- Markdown 链接、相对图片路径和 GitHub Actions 徽章均可静态检查。
