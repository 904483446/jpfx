- 更新 README 的当前阶段、已完成能力、验证方式与后续路线。

- 不实现退出登录。现有认证、Cookie 会话、凭据型 CORS 与统一中文错误模式不变。

- 不实现空间编辑、删除、详情数据加载、文档上传、知识库、RAG、竞品分析、报告、模型设置或任何 V0.2+ 功能。
- 不读取、输出、提交或修改任何真实 `.env`、`.env.local`、密钥、Cookie 或 Token。
- 不修改 `main`，所有变更只发生在 Task 10 分支 worktree。

## 方案与文件边界

### 1. README 对齐

更新 `README.md`，将当前状态准确表述为：Task 0–9 已完成，Task 10 负责收尾。README 将列出已具备的注册、登录、当前用户校验、产品空间列表与创建、详情占位页能力，并明确 V0.2 从空间内文档上传开始。

README 不把未实现的退出登录或默认知识库表述为已交付能力。

### 2. 非敏感环境示例

新增或补全根目录 `.env.example`。模板仅使用安全占位符，不从任何真实环境文件复制内容。每个变量将附带简短用途说明，并保持前后端现有命名约定。

该文件是提交到仓库的配置样例，不是运行时凭据文件；用户仍自行在本地创建并维护真实环境文件。

### 3. 收尾记录

新增 Task 10 收尾记录，固定以下信息：

- 本次检查的命令与结果。

记录不声称未实际执行的集成或浏览器验证已经通过。

## 验证策略

在不读取环境文件的前提下，按项目既有命令执行：

1. 后端单元测试与既有静态检查。
2. 前端测试、路由检查、TypeScript、lint、生产构建与生产依赖审计。
3. 对需要数据库、前后端服务或本地环境文件的验证，只有在用户已启动相应服务且环境可用时才执行；否则在收尾记录中标记为未执行，不以替代性测试冒充通过。

当前新 worktree 的前端依赖尚未就绪，`npm.cmd run test` 报告找不到 `vitest`。实施计划会将依赖准备与基线验证列为前置步骤，并在开始修改文档前先解决或如实记录该阻塞。

## 验收标准

- README 与已合并的 Task 0–9 功能一致，不夸大未实现能力。
- `.env.example` 不含真实凭据或从真实环境文件读取的值。
- 收尾记录可复现地说明每项检查结果与限制。
- Task 10 变更不触及应用功能代码、认证语义、空间 API 或数据库迁移。
- V0.2 入口和未完成事项明确，后续开发可从最新 `main` 创建独立 worktree 继续。
